How I Can Help

Five ways I can help your product or team.

End-to-End Delivery

I can own a product end to end: the database, the admin tools your staff use, the customer app, and the release to the App Store and Google Play. You work with one person who understands how every part fits together.

Example
DriveOnline, where I led development of both the driver app and the back office.
  • Laravel
  • Flutter
  • Livewire
  • React
  • Go

Mobile Apps

I build iPhone and Android apps from a single codebase, add native code where a feature needs it, and automate releases so updates go out often and safely.

Example
More than 110 releases of Package.ai's operator app.
  • Flutter
  • Swift
  • Kotlin
  • Fastlane

Offline Reliability

I design software that keeps working when the internet doesn't. It also connects to the devices your operations depend on, such as receipt printers and point-of-sale terminals.

Example
ParcelHive's offline storage, QR waybills, and printed receipts, plus myBES ticket sales on point-of-sale devices.
  • Offline Sync
  • Thermal Printing
  • Android POS
  • Mobile Money

AI Integration

I build AI features that run on the user's own phone, so private information never leaves the device, and answers can show where they came from.

Example
Native iOS and Android AI assistants for BeeHyv, built on Google's Gemma.
  • On-Device AI
  • Gemma
  • Document Search (RAG)

Engineering Team

I document decisions, write coding standards and onboarding guides, review code, and set up monitoring so problems are caught early. Others can pick up the work long after I've moved on.

Example
Kaiteki.ai's developer, architecture, and testing guides, and automated checks that fail any build where test coverage drops below 70%.
  • Documentation
  • Code Review
  • GitHub Actions
  • Sentry

About

Eyram, /ɛjɪˈram/

My preferred name.

Most of my work sits where software meets daily operations: drivers on inter-city routes, couriers working from stations, staff selling tickets at bus terminals. That means designing for unreliable connections, special-purpose hardware, and people with other things to watch.

On a team I usually own a product end to end: architecture, code, documentation, and the release pipeline. I write things down, from coding standards to onboarding guides for testers, so decisions stay clear after I've moved on.

Away from the keyboard: swimming, reading, and the occasional detour into creative design.
